# BB-17 QA Suite Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convert BB-07 through BB-16 acceptance requirements into validated, repeatable release evidence and close the remaining browser/CI gaps.

**Architecture:** A versioned JSON registry maps stable requirement IDs to existing automated tests or justified manual checks. A small TypeScript validator makes stale paths, missing titles, duplicate IDs, and unjustified manual evidence fail in Vitest; targeted Playwright additions cover only observed gaps, while CI retains failure artifacts.

**Tech Stack:** TypeScript 6, Vitest 5, Playwright 1.63, axe-core, Next.js 16.4, GitHub Actions, Supabase pgTAP/cloud evidence.

**Spec:** `docs/superpowers/specs/2026-10-11-bb-17-qa-suite-design.md`

- Work only in `C:\Users\El Yisus Pai\Desktop\Proyectos\bunker-bb17` on `codex/bb-17-qa-suite`.

- Secrets and service-role credentials never enter Playwright.
- Cloud-only evidence must remain explicit and cannot become a passing local skip.
- Follow red-green-refactor for every new validator or behavior.

## Review Focus

- A registry entry points to a file that exists but a renamed test title: validation must fail.
- A manual entry omits its reason or checklist anchor: validation must fail.
- Two entries reuse one stable ID: validation must fail.
- One of the required BB-07…BB-17 IDs is omitted: completeness validation must fail.
- A Playwright failure occurs before retry: screenshot, trace and raw test output must remain uploadable.
